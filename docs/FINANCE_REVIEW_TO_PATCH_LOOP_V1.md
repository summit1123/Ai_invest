# FINANCE_REVIEW_TO_PATCH_LOOP_V1.md

## 목적
finance 조직의 공식 운영 루프를
**review → analysis → patch → validate** 구조로 고정한다.

이 문서는 일간 리뷰/운영 채널에서 나온 내용을 실제 개선 행동으로 연결하기 위한 기준이다.

---

## 1. 기본 원칙
1. 리뷰는 단순 보고로 끝내지 않는다
2. 리뷰는 반드시 분석 또는 액션으로 이어진다
3. 안전한 안정화 수정은 Jarvis가 직접 진행할 수 있다
4. 리스크/전략 영향이 큰 변경은 사용자 승인 후 진행한다
5. 수정 후에는 반드시 다음 리뷰에서 효과를 검증한다

---

## 2. 입력
다음이 finance 개선 루프의 입력이 된다.
- `finance:runtime-check`
- `finance:daily-review-lite`
- pause / recon / order_rejected alert
- 운영자 메모
- 수동 회의 결과

---

## 3. 루프
### Step 1. Review
리뷰에서 아래를 뽑는다.
- 오늘 핵심 이슈
- 반복 패턴
- 개선 우선순위
- 추천 수정 항목

### Step 2. Analysis
Jarvis가 아래를 판단한다.
- 이 이슈가 단순 노이즈인지
- 구조적 문제인지
- rules 조정 문제인지
- 코드 수정 문제인지
- 리스크 영향이 큰지 작은지

### Step 3. Patch
#### 직접 진행 가능
- 알림 구조 조정
- 로그/가시성 개선
- 운영 안정화 수정
- 명백한 버그 수정
- 안전 범위 내 rules/threshold 미세 조정

#### 승인 후 진행
- 진입 조건 완화/강화가 손익 구조에 큰 영향이 있을 때
- 포지션 크기/손실 한도/실거래 정책 변경
- 전략 방향 자체 변경

### Step 4. Validate
다음 날/다음 리뷰에서 확인한다.
- 거래 수 변화
- 손익 변화
- drawdown 변화
- order reject 변화
- recon/pause 재발 여부
- 기대값 개선 여부

---

## 4. 의사결정 기준
### 바로 수정해도 되는 케이스
- 명백한 버그
- 권한/연결/알림 문제
- 과도한 소음 감소
- 안전한 미세 조정

### 물어봐야 하는 케이스
- 거래가 많아지거나 적어지는 방향성 변경
- 손실 허용 범위 확대
- 공격적 진입 증가
- 실거래 정책 변경

---

## 5. 한 줄 결론
finance 조직은 리뷰를 읽고 끝내는 조직이 아니라,
**리뷰를 분석하고, 수정하고, 다시 검증해 점점 더 나아지는 시스템**을 굴리는 조직이다.
