# FINANCE_GROWTH_LOOP_V1.md

## 목적
finance 조직이 단순 감시 조직을 넘어,
`AI_invest`를 시간이 지날수록 더 똑똑하고 더 수익성 있게 만드는 운영 루프를 정의한다.

---

## 1. 문제 정의
이 시스템의 원래 목적은 단순 자동매매가 아니다.

목표는:
- AI가 로그와 결과를 계속 읽고
- 회의/리뷰를 통해 학습하고
- 축적된 데이터를 바탕으로
- 점점 더 나은 운영/판단/구조로 진화하는 것
이다.

즉,
finance 조직은 단순 유지보수가 아니라
**데이터 축적 → 회의 → 개선 → 반영 → 재학습** 루프를 굴리는 조직이어야 한다.

---

## 2. 수익을 더 만들 수 있는 구조의 본질
수익을 늘리는 가장 직접적인 방법은
단순히 더 자주 거래하는 것이 아니라,
**좋은 의사결정의 비율을 높이고 나쁜 손실 패턴을 줄이는 것**이다.

이를 위해 finance 조직은 아래 4개 층을 가져야 한다.

### Layer 1. Observability
- 지금 무슨 일이 일어났는지 보인다
- 이벤트/체결/경보/중단 이유가 남는다

### Layer 2. Review
- 하루/주 단위로 결과를 해석한다
- 손실 원인과 반복 실패 패턴을 찾는다

### Layer 3. Decision Improvement
- 규칙, 파라미터, 알림, 복구 로직을 개선한다
- 필요 시 코드 수정으로 이어진다

### Layer 4. Learning Memory
- 무엇이 잘 통했고 무엇이 실패했는지 축적한다
- 이후 회의/튜닝/전략에 반영한다

---

## 3. 성장 루프
### Step 1. 데이터 축적
입력:
- events
- runs
- fills
- deliveries
- pause_log
- pnl snapshots

### Step 2. 운영 회의
형태:
- daily review
- weekly improvement
- incident review

질문:
- 어디서 돈을 잃었는가?
- 어떤 신호가 거짓 양성/거짓 음성이었는가?
- 어떤 경보가 소음이었는가?
- 어떤 규칙이 과도하게 보수적/공격적이었는가?

### Step 3. 개선안 생성
출력:
- 규칙 조정
- threshold 변경
- notification dedupe 조정
- pause/recovery 로직 개선
- 코드 수정 과제

### Step 4. 반영
- rules.yaml 변경
- 코드 변경
- 운영 정책 변경
- 오케스트레이터 반영/재기동

### Step 5. 검증
- 이후 며칠 성능 비교
- drawdown 감소 여부
- order reject 감소 여부
- recon fail 감소 여부
- expectancy 개선 여부

이 과정을 반복하면,
시스템은 단순 자동매매기가 아니라
**운영 데이터를 먹고 점진적으로 좋아지는 AI-native trading system**이 된다.

---

## 4. finance 조직에서 AI가 돈을 더 벌게 만드는 방식
### 직접적으로
- 손실 패턴 조기 탐지
- 쓸데없는 진입 감소
- 오류/중단 시간 축소
- 복구 시간 단축
- 알림 품질 개선

### 간접적으로
- 회의 품질 향상
- 개선 속도 향상
- 반복 학습 자산 축적
- 실험-검증 루프 단축

즉,
AI의 역할은 미래를 마술처럼 맞추는 것이 아니라,
**운영 체계를 점점 더 좋게 만들어 기대값을 높이는 것**이다.

## 6. 한 줄 결론
finance 조직의 목표는 단순히 현재 시스템을 지키는 것이 아니라,
**축적된 운영 데이터와 반복 회의를 바탕으로 시스템이 점점 더 똑똑하고 더 수익성 있게 진화하도록 만드는 것**이다.
